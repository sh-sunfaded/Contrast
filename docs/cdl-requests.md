## 結論

**現時点（U2・U3）で、CDL の破壊的変更は不要です。** U4 以降で、確認が必要な点があります。

根拠の限界: 根拠は `report-u0-ui-update.md` §3（CDL rev `0d252db` の `docs/SPEC.md` と `cdl-host/src/lib.rs`）です。2026-11-12 に CDL に小さな変更があったため、現行の公開 API とは差がありえます。私は CDL のソースを読んでいません。要求を出す前に、Claude Code が現行の rev で §3 の表を再確認する必要があります（調査のみ、CDL は変更しない）。

## 2. 非破壊の提案（必須ではない。CDL 側の判断）

### 提案 CDL-1: `Literal`（またはリテラルユニオンを作るヘルパー）を `cdl-host` から再公開する
- 現状: `Ty::Literal(Literal)` はあるが、`Literal` が `cdl-host` から再公開されていない（`lib.rs:21-22`）。そのため、曲線名（`easeOutCubic` など）やキー名を `string` + 変換での検査にしている
- 効果: スキーマ側で未知の曲線名を拒否でき、CT071 の一部を CDL の診断に任せられる
- 破壊性: なし（追加のみ、既存の挙動を変えない）
- 緊急度: 低。Contrast は変換での検査で足りている

### 提案 CDL-2: `Node` が prop の位置（span）を返せるようにする
- 現状: 値の診断は要素単位の位置まで（契約 4 節「props に位置がない」）。INV-T1・INV-A1 の「位置付き診断」が、prop 単位にならない
- 効果: `duration` や `l` のどの prop が不正かを、行・列で指せる
- 破壊性: なし（API の追加）。ただし、CDL の AST が prop の span を保持しているかは未確認
- 緊急度: 低〜中。診断の質の改善

## 4. React 風の方向（2026-11-12 の方針）との関係

CDL を React 風の宣言的 UI に近づける方針（破壊的更新を許容）は、U3 までの仕様には**影響しません**。`<Motion>`・`<Tiers>` は既存の要素木の形で書けるためです。この方針が効くのは U4 で、`view = f(state)`（`Env` を受けるルート、`when`）の部分です。Q-C3〜C5 の結果が、その方針で CDL を変えるかどうかの判断材料になります。
